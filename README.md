# AI Log Analyzer — учебный прототип

Синтетические связанные трассы пяти микросервисов. Данные, метки и экономические параметры демонстрационные; это **не реальные производственные логи**.

## Установка и воспроизводимый запуск

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python generate_data.py
python prepare_data.py
python run.py --trace trace-0000
pytest -q
```

`generate_data.py` использует фиксированный seed. `data/incident_labels.csv` содержит эталонные причины; **этот файл нельзя передавать агенту** при диагностике.

## OpenRouter

```bash
cp .env.example .env
# Заполните OPENROUTER_API_KEY и OPENROUTER_MODEL в .env
set -a; source .env; set +a
python run.py --trace trace-0000 --llm
```

Модель должна быть актуальной бесплатной моделью OpenRouter (`:free`). Реальный вызов API ещё не подтверждён. Не помещайте ключи API в git.

## Ограничения

Сценарии заданы вручную и повторяются с небольшими изменениями времени; разнообразие сообщений ограничено. Наличие эталонной причины не гарантирует, что её можно однозначно вывести из любого набора логов. Потеря части событий при очистке может ухудшать диагностику. Модель может ошибаться; решения об изменениях инфраструктуры остаются за разработчиком.

## Версия 3: агент с инструментами

`src/agent.py` использует LangChain `create_agent` и два read-only инструмента:
`get_trace` (события конкретного запроса) и `get_service_errors` (ошибки сервиса в других трассах).
Ответ валидируется Pydantic и требует проверки разработчиком.

```bash
python run.py --trace trace-0000 --llm
```

**Важно:** не каждая бесплатная модель OpenRouter поддерживает вызов инструментов (`tool calling`).
При ошибке API выберите другую бесплатную модель с поддержкой tools. Неизвестно,
какая бесплатная модель будет доступна в момент запуска. Реальные ответы модели и
точность диагностики не проверялись: для этого нужен пользовательский API-ключ.
Сами логи могут содержать чувствительные данные; для реальных логов требуется
обезличивание перед отправкой во внешний API.

## Версия 4: проверка качества на реальных ответах модели

После настройки `.env` запустите:

```bash
python evaluate_agent.py --per-class 1   # 6 вызовов LLM: по одному на сценарий
python evaluate_agent.py --per-class 2   # 12 вызовов LLM: по два на сценарий
pytest -q
```

Результаты каждого вызова немедленно сохраняются в `results/evaluation_*.json`:
эталонная метка, предполагаемый класс, полный ответ модели, время выполнения,
ошибка (если возникла). Итоговый `summary` содержит количество попыток,
успешных ответов, совпадений, долю совпадений и показатели по каждому классу.
Если запрос завершится с ошибкой, это не считается верным диагнозом.

**Важно:** автоматическое сопоставление использует простые ключевые слова из
`evaluate_agent.py`, поэтому это *предварительная* оценка, а не доказанная
точность модели. Неоднозначные диагнозы получают `unclassified`. Для отчёта
необходимо вручную просмотреть ошибки и случаи `unclassified`. Эталонные
метки считывает только скрипт оценки; агент не получает этот файл.

Файлы результатов могут содержать фрагменты логов: не публикуйте их без проверки.
